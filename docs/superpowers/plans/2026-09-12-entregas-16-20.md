# Entregas 16 a 20 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar documentos/anexos, OCR local opcional, relatórios avançados, hardware opcional e runtime Desktop final no ArtiSys Almoxarifado.

**Architecture:** Manter o domínio de estoque/compras isolado e adicionar serviços focados (`documents`, `ocr`, `analytics`, `hardware`, `desktop-runtime`) atrás de contratos locais. Reutilizar módulos pinados de `vendor/utilidades` apenas por adapters; persistência continua local em `.data`, API/PWA continua LAN-first e hardware/OCR devem degradar para `unavailable` sem derrubar a operação manual.

**Tech Stack:** Node.js 22+, ES modules no produto, JSON repository local, HTTP local, PWA vanilla, `@artisys/upload`, `@artisys/ocr`, `@artisys/serialport`, `@artisys/printing`, `@artisys/desktop-shell`.

**Spec:** `docs/superpowers/specs/2026-09-12-entregas-16-20-design.md`

## Global Constraints

- Host principal: Windows Desktop.
- PWA/API disponíveis na LAN sem internet obrigatória.
- Dados operacionais e arquivos permanecem locais por padrão.
- Núcleo com custo obrigatório R$ 0; nenhuma cloud ou serviço pago como dependência silenciosa.
- Anexo: máximo padrão de 15 MB; PDF/JPEG/PNG/WebP/texto simples.
- Arquivos físicos ficam em `.data/documents/` com nome interno; nunca usar nome fornecido pelo usuário como path.
- Exclusão de documento: manter metadado auditável e remover o arquivo físico.
- OCR e hardware são opcionais; indisponibilidade não pode bloquear o sistema.
- Autorização deve ser aplicada server-side.
- Não executar homologação física de hardware/celular/tablet nesta etapa.
- Não disparar CI remoto durante implementação intermediária.
- O instalador `.exe` continua fora do escopo e pertence à Entrega 21.

// document-storage.mjs
export function createDocumentStorage({rootDir,maxFileSize=15*1024*1024}) {
  return {
    async write({id,bytes}) {
      const body=Buffer.from(bytes);
      if(body.length>maxFileSize) throw new DomainError('DOCUMENT_TOO_LARGE','document exceeds 15 MB');
      const storageName=`${id}.bin`;
      const file=path.resolve(rootDir,storageName);
      if(!file.startsWith(`${path.resolve(rootDir)}${path.sep}`)) throw new DomainError('INVALID_DOCUMENT','invalid storage path');
      await mkdir(rootDir,{recursive:true});
      await writeFile(file,body);
      return {storageName,size:body.length,sha256:createHash('sha256').update(body).digest('hex')};
    },
    async read(storageName) { /* resolve dentro de rootDir e readFile */ },
    async remove(storageName) { /* unlink; ENOENT é idempotente */ }
  };
}
```

Use `validateUploadBatch([{name:originalName,size:bytes.length,type:mimeType}], {maxFiles:1,maxFileSize:15*1024*1024,accept:['application/pdf','image/jpeg','image/png','image/webp','text/plain']})`; rejeições viram `INVALID_DOCUMENT` ou `DOCUMENT_TOO_LARGE`.

Persistir metadado:

export function createOcrAdapter({providers={}}={}) {
  return {
    available:()=>Object.values(providers).some((provider)=>typeof provider?.recognize==='function'),
    async recognize(input) {
      if(!this.available()) throw new DomainError('OCR_UNAVAILABLE','local OCR provider is unavailable');
      try { return await executeOcr(providers,{...input,environment:'native',prefer:'auto'}); }
      catch(error) { throw new DomainError('OCR_FAILED','OCR processing failed',{cause:error.message}); }
    }
  };
}
```
